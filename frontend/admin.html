    1. How the pieces fit

    • Server (Flask, backend/app.py) — stores users, vehicles, photos, fingerprints and logs; serves this admin portal and the staff portal.
    • Camera computer (anpr/live_capture.py) — watches the camera nonstop, reads plates, reports them to the server, then tells the ESP32 what to do.
    • Gate (ESP32 + fingerprint sensor + keypad + servo) — for a registered car it asks for a fingerprint first, then an OTP if the driver isn't the owner. Visitor cars just get the gate opened.
    • Admin portal (this page) — register users, enroll fingerprints, watch everything live.
    • Staff portal (/) — registered users generate OTPs for other drivers of their car.

    All three devices (laptop, camera computer, ESP32) must be on the same Wi-Fi network for local testing. The camera computer can be the same laptop that runs the server.

    2. Run the server locally

    In PowerShell, from the project folder:

    $env:DEVICE_API_KEY = ""
.venv\Scripts\python.exe backend\app.py
    • The server runs on port 5000 and is reachable from other devices on your Wi-Fi (it listens on all addresses).
    • Admin portal: http://localhost:5000/admin · Staff portal: http://localhost:5000/
    • Find your laptop's Wi-Fi address with ipconfig (the IPv4 Address, e.g. 192.168.1.50). The ESP32 needs it.
    • Emails and SMS aren't really sent locally — OTP emails and password-reset codes are printed in this server window instead.

    Device key: the line $env:DEVICE_API_KEY = "" turns off the device key check for local testing. If you'd rather keep a key, set the same value here, in the camera computer's window, and in the ESP32's secrets.h. If they don't match you'll get "Invalid or missing device key".

    Windows Firewall: the first time, Windows may ask whether Python can accept connections — allow it on private networks, or the ESP32 won't reach the server.

    3. Register a user

    1. Open Register user.
    2. Fill in identity, contact and vehicle details. Use a real plate you can show the camera (e.g. your own car, or a printed plate photo).
    3. Add a passport photo and a front photo of the car with the plate visible. Large phone photos are fine — they're shrunk before uploading.
    4. Fingerprints are optional here; you can add them on the user's profile later (next step).
    5. Press Register user. Note the temporary password shown — it's for the staff portal.

    Check it worked: the user appears in Registered users; click them to see the profile, photos and vehicle.

    4. Enroll fingerprints

    Fingerprints are stored on the server, so you can enroll from any R307-type sensor connected to the computer you're using. Needs Chrome or Edge, on localhost or an https:// address.

    Option A — use the gate's own sensor (no spare sensor)

    1. Flash the latest firmware to the ESP32 (section 5).
    2. With the gate idle, press D on the keypad, then #. It restarts and shows USB ENROLL MODE. The gate doesn't open cars in this mode.
    3. Plug the ESP32 into this computer with its USB cable. Close the Arduino Serial Monitor — only one program can use the port.
    4. Open the user's profile here → Connect sensor → choose the ESP32's COM port in the popup.
    5. Pick a finger → Scan finger → place, lift, place again as prompted. Enroll at least two fingers.
    6. When finished, press D on the keypad to go back to normal gate mode.

    Option B — spare sensor + USB-TTL adapter

    Wire sensor TX → adapter RX, sensor RX → adapter TX, VCC → 5V, GND → GND. Plug in, then same as steps 4–5 above, choosing the adapter's COM port.

    If you don't see a COM port in the popup, the USB driver may be missing (CH340/CP2102 drivers), or another program has the port open.

    5. Set up the gate (ESP32)

    1. In esp32/smart_gate_esp32/secrets.h: your Wi-Fi name and password, and DEVICE_API_KEY (empty "" for local testing, matching step 2).
    2. In smart_gate_esp32.ino, near the top, point it at your laptop for local testing: 
      // const char* SERVER_URL = "https://verigate-ry5y.onrender.com";
const char* SERVER_URL = "http://192.168.1.50:5000";   // your laptop's IPv4 address
      Switch it back to the Render address before deploying.
    3. Arduino IDE: board ESP32S3 Dev Module, PSRAM OPI PSRAM, Flash size 16MB. Upload.
    4. Open the Serial Monitor at 115200 baud. You should see Wi-Fi connected, the ESP32's IP address, and [HEARTBEAT] HTTP: 200.
    5. Here on the Overview, Gate controller should turn Online within a minute.

    6. Run the camera (ANPR)

    On the camera computer (can be this laptop), in a new PowerShell window from the project folder:

    cd anpr
$env:SERVER_URL = "http://localhost:5000"     # or http://LAPTOP-IP:5000 from another computer
$env:ESP32_URL  = "http://192.168.1.80"       # the ESP32's IP (shown on its screen / Serial Monitor)
$env:DEVICE_API_KEY = ""
..\.venv\Scripts\python.exe live_capture.py

    You should see ANPR live capture started. Within a few seconds the ANPR camera turns Online here and the picture appears on the Overview and the Live monitor.

    Choosing the camera

    • Laptop / USB webcam: default. If the wrong camera opens, try $env:CAMERA_INDEX = "1".
    • Phone as camera: install an IP-camera app (e.g. "IP Webcam" on Android), start it, then $env:CAMERA_INDEX = "http://PHONE-IP:8080/video".
    • No camera at all: use a video file of a car driving up: $env:CAMERA_INDEX = "C:\path\to\clip.mp4".
    • Raspberry Pi camera module: CAMERA_BACKEND=picamera2.

    Useful settings while testing

    CONFIRM_READSSame plate must be read this many times before acting (default 2). Set 1 for faster tests.
    COOLDOWN_SECONDSIgnore the same plate for this long after handling it (default 30). Lower it to re-test the same car quickly.
    PREFILTERmotion (default) reads plates when something moves. none reads every frame — use this when holding a still photo up to the camera.
    ANPR_EVENT_TYPEentry or exit for this camera.
    CAMERA_PUSH_INTERVALSeconds between live frames sent to the monitor (default 1, 0 = off).

    If the ESP32 isn't set up yet, leave ESP32_URL as it is — plates are still detected and show up here; the script just prints that it couldn't reach the gate.

    7. Test a full gate visit

    Keep the Live monitor open while you do these — every step appears there as it happens.

    A. Visitor car

    Show the camera a plate that isn't registered. Expect: monitor shows Visitor – gate opened, servo lifts for 5 s.

    B. Owner driving

    1. Show the camera the registered plate. ESP32 beeps twice, shows STAFF VEHICLE, then SCAN FINGER.
    2. Scan one of the owner's enrolled fingers. Expect: OWNER VERIFIED, gate opens; monitor shows Access granted – owner verified by fingerprint.

    C. Someone else driving (OTP)

    1. Generate an OTP from the staff portal first (section 8).
    2. Show the registered plate, then scan a finger that is not the owner's. Expect: NOT THE OWNER – Enter owner's OTP. The keypad only works after a finger has been scanned.
    3. Type the 6-digit OTP. Expect: gate opens; monitor shows Access granted – driver verified by OTP. The OTP can't be reused.

    D. Failures

    • Wrong OTP: OTP REJECTED, 3 tries in total, then ACCESS DENIED.
    • Do nothing for 90 seconds: TIMEOUT, gate stays closed.
    • User with no fingerprints enrolled: gate goes straight to OTP.

    8. Test the staff side (OTPs)

    1. Open the staff portal in a different browser or private window (staff and admin logins are separate).
    2. Log in with the user's ID number and the temporary password from registration (locally it's local-dev-only).
    3. Generate an OTP. Locally the email isn't sent — the code is on screen and also printed in the server window.
    4. Try Forgot password?: the reset code is printed in the server window locally.
    5. Confirm admin login details are rejected on the staff login, and vice versa.

    9. Live monitor & records

    • Live monitor — meant for the big screen. Press Full screen. Shows the camera, the current car's state, owner photo, and the camera frame beside the registered car photo so the guard can compare them.
    • Access log — every fingerprint/OTP decision; filter by method, direction, result and dates.
    • Camera detections — every plate the camera read, with the frame it came from (the latest 300 frames are kept).
    • Overview — today's numbers and whether the gate and camera are online.

    10. Testing on Render instead

    1. Merge the admin-dashboard-server-fingerprints branch into main and push; wait for Render to redeploy.
    2. On Render, keep the app to one worker (live camera and logins are held in memory).
    3. Admin portal: https://verigate-ry5y.onrender.com/admin.
    4. ESP32: switch SERVER_URL back to the Render address; DEVICE_API_KEY in secrets.h must match Render's.
    5. Camera computer: SERVER_URL=https://verigate-ry5y.onrender.com and the same DEVICE_API_KEY.
    6. Fingerprint enrollment works the same way from Chrome on the Render address.

    11. Troubleshooting

    "Invalid or missing device key"DEVICE_API_KEY differs between the server, camera computer and ESP32. Make them identical (or all empty locally).
    Gate controller stays OfflineWrong SERVER_URL in the firmware, laptop firewall blocking port 5000, or ESP32 on a different Wi-Fi.
    Camera Online but no plates detectedPlate too small or blurry — move closer; try PREFILTER=none and CONFIRM_READS=1.
    Plate detected but gate does nothingCamera computer can't reach the ESP32 — set ESP32_URL to the ESP32's IP instead of verigate.local.
    "Connect sensor" shows no portsUse Chrome/Edge; close Arduino Serial Monitor; install the CH340/CP2102 driver.
    Sensor "stopped responding"Check TX/RX aren't swapped; for Option A, make sure the gate shows USB ENROLL MODE.
    Owner's finger says NOT THE OWNERRe-enroll that finger, pressing flat both times; enroll a second finger as backup.
    Live monitor logs you outThe server restarted (logins are in memory) — just log in again.
