# Smart Gate

Smart Gate is a vehicle-access system that combines a web app, a server, and
gate-side hardware. It identifies vehicles with automatic number plate
recognition (ANPR), then lets a registered vehicle owner verify access with a
fingerprint or a one-time password (OTP). Staff and administrators can manage
access and review gate activity in the web interface.

## How it works

1. A camera and the ANPR service read a vehicle's plate and report it to the
   backend.
2. The backend looks up the registered vehicle and records the detection.
3. The ESP32 prompts the driver to verify with a fingerprint. If the driver
   isn't the vehicle owner, they can enter an OTP generated by the owner.
4. The ESP32 opens the barrier after successful verification and reports gate
   events to the backend.
5. Staff and administrators use the web app to manage access and monitor
   activity.

The backend serves the frontend as well as the API:

- `/` — staff login and dashboard
- `/admin` — administrator login and management

## Project components

| Directory | Purpose |
|---|---|
| `backend/` | Flask API, SQLAlchemy models, authentication, and database access |
| `frontend/` | Staff and administrator pages, including OTP and activity views |
| `esp32/smart_gate_esp32/` | ESP32-S3 gate controller firmware |
| `anpr/` | Camera capture, plate recognition, and Raspberry Pi service setup |

The backend uses SQLite by default when `DATABASE_URL` is unset. Set
`DATABASE_URL` to a PostgreSQL connection string for a shared or hosted
deployment.

## Run the web app locally

You need Python and pip. From the repository root, create a local environment
and install the backend dependencies:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r backend\requirements.txt
```

Create your local settings file from the example:

```powershell
Copy-Item .env.example .env
notepad .env
```

Set unique values for `DEFAULT_STAFF_PASSWORD` and
`DEFAULT_ADMIN_PASSWORD` before starting the backend. For a local SQLite
database, leave `DATABASE_URL` unset or remove its example value. The database
file is created under `backend/data/` on startup.

Start the development server from the repository root:

```powershell
python backend\app.py
```

Open [http://localhost:5000](http://localhost:5000) for the staff app or
[http://localhost:5000/admin](http://localhost:5000/admin) for the
administrator app. The development server runs with Flask debug mode; do not
use it for a public deployment.

On the first run, the backend creates the database tables and adds sample
records if the database is empty. Remove or replace development accounts and
sample data before using the system with real users.

## Configuration

The repository includes [.env.example](.env.example). Copy it to `.env` and
replace its placeholders. The `.env` file is ignored by Git and must never be
committed.

Important settings:

| Variable | Purpose |
|---|---|
| `DEFAULT_STAFF_PASSWORD` | Initial password assigned to newly created staff accounts |
| `DEFAULT_ADMIN_PASSWORD` | Password for the seeded `GateAdmin` account |
| `DATABASE_URL` | Optional database URL; SQLite is used when unset |
| `DEVICE_API_KEY` | Shared secret for device-to-backend requests; configure the same value on the backend, ESP32, and ANPR device |
| `SERVER_URL` | Backend URL used by devices and as a fallback for reset links |
| `PUBLIC_BASE_URL` | Optional public URL used to construct password-reset links |
| `RESEND_API_KEY` | Optional Resend API key for sending password-reset emails |
| `RESEND_FROM_EMAIL` | Optional verified sender address for Resend |

When email delivery is not configured, password-reset messages are written to
the backend console for local development.

## Gate hardware and ANPR

- **ESP32:** Set up the board and peripherals, then copy
  `esp32/smart_gate_esp32/secrets.h.example` to `secrets.h` in the same folder.
  Add the Wi-Fi credentials, backend URL, and matching `DEVICE_API_KEY` before
  compiling and uploading the sketch. Keep `secrets.h` private.
- **Raspberry Pi camera:** Follow the
  [Raspberry Pi ANPR setup guide](anpr/RASPBERRY_PI.md) to install camera
  dependencies, configure the service, and run plate recognition at startup.
  ANPR configuration options are documented at the top of
  `anpr/live_capture.py`.

Plate recognition performance depends on camera placement, plate visibility,
lighting, and hardware. Test the complete gate flow in the intended
environment before relying on it.

## Deployment notes

- Use HTTPS for the public web app and API.
- Set strong, unique passwords and a random `DEVICE_API_KEY`; never use
  placeholder or development credentials in production.
- Configure PostgreSQL and back it up regularly when persistent hosted data is
  required.
- Run the Flask app with a production WSGI server such as Gunicorn rather than
  Flask's debug server. For example, from `backend/`:

  ```sh
  gunicorn --bind 0.0.0.0:5000 app:app
  ```

- Protect staff information, vehicle details, images, and biometric templates
  as sensitive data. Limit access to the server and database, and retain only
  data needed for operation.
